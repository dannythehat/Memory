### D-054 amendment: point-in-time (vintaged) news (ChatGPT; applied by Claude before the first real detector run)
- **No hindsight.** `news_weeks` (newest fetch authoritative) is removed. Every download is an immutable vintage in `news_fetches`/`news_events` (raw XML, hash, fetch time, clock decision, events). An evaluation at decision time T (the signal time; for research clocks the bar's completion time) uses, per calendar week, the latest ACCEPTED vintage with `fetched_utc_ms <= T`. `covered(a, b, as_of, kind)` and `events_between(a, b, as_of)` both resolve the vintage from `as_of`; the strategy layer passes `utc(signal_time)`. A later fetch changes what is known from then on, never a historical replay. A download identical to the latest one of the same URL is a no-op; content equal to an older vintage but different from the latest is stored as a new vintage (the calendar changed back).
- **Test (fetch A before the signal, fetch B revising the event later):** the historical signal still uses A (`SKIPPED_NEWS`), a later signal uses B (event moved out of K2), and a signal before any vintage is `NOT_EVALUATED_NEWS_COVERAGE` (`tests_unit/test_news_pit.py`, on golden vector GV-P08-V11).
- **Untimed items.** Ordinary untimed / All Day items stay informational. An untimed USD high-impact event on a day touched by the window makes the HIGH calendar unusable for that window; an untimed item that maps to NFP/CPI/FOMC (any impact label) does the same for the MAJOR filter. Both give `NOT_EVALUATED_NEWS_COVERAGE`, never "no event".
- **Bug found and fixed while doing this:** the MAJOR filter blocks a signal in [event-60, event+30] min, so the relevant events lie in [signal-30, signal+60] min; the coverage window I had used was the mirror image ([signal-60, signal+30]). ### D-055 Shared-database locking (engineering, Claude)

### D-058 first real result and audit fix (Claude)
