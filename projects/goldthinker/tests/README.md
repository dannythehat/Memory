# GoldThinker golden test vectors — pack GV-0.1

For `CANDLE_SPEC_V1.md` **Draft 0.2.2** (2026-09-30). Status: **proposed, for review** — nothing here is approved by the owner and nothing has been built. This is the test set an implementation must pass *before* any detector code is trusted (D-005, D-021, D-030).

## The rule these vectors follow

**The spec was not edited to make a test pass.** Where a vector could not be written without choosing between readings, it is **BLOCKED** (no expected value asserted; candidate rulings listed) or **PROVISIONAL** (the assumption is stated), and the item is in `AMBIGUITIES.md` for review. 29 items were found.

## Conventions (fixtures)

- **Test account (fixture, not Vantage's real specification):** tick size 0.01, tick value $1.00 per tick per lot, lot step 0.01, minimum lot 0.01, default spread 0.20, commission 0 unless stated, reference equity $10,000, 1R = $100.
- **Test calendar (fixture; the real Vantage calendar is still "TO CONFIRM"):** market open Sunday 23:00 UTC to Friday 22:00 UTC; daily pause Monday-Thursday 22:00-23:00 UTC; server time UTC+1 with no DST for D1/W1/MN1 boundaries.
- **Exact arithmetic.** All comparisons are exact decimal. Boundary vectors are exactly on the line (spec A-22 asks for a stated precision rule).
- **Context injection.** In pattern vectors ATR is 4.00 unless stated and trend/zones/swings/RSI are supplied; the global vectors test how those values are *computed* from bars. Bars are **bid** OHLC; ticks carry bid and ask. Detection uses bid (the chart); BUY executes at the ask, SELL at the bid.
- **Every boundary probe names the clause it isolates.** The calculator checked that exactly that clause fails and no other (the `failing clause` column).
- Tick times inside a vector are absolute UTC in the JSON.

## How the vectors were checked

Every expected value was written by hand or by a simple stated formula first, then compared with an independent scratch calculator written directly from the spec text (exact rational arithmetic, per-clause evaluation, calendar, ticks, hub aggregation). All 1328 non-blocked vectors now agree with it. A few dozen disagreements during writing were slips in my own arithmetic or bar geometry and were corrected in the vectors, **not** in the spec. **Limits of that check:** the same author wrote the vectors and the calculator from the same reading of the spec, so it proves internal consistency and arithmetic, not that the spec's intent was read correctly; the independent reviewer should check the ambiguity readings, and a real implementation should later be run against `golden_vectors.json`. The calculator is scratch code and is not stored in the repository (D-005: no build code before the foundations are agreed).

## Findings in one paragraph

No rule turned out to be impossible to satisfy on its own, but the vectors exposed **4 high-severity gaps** (dead-zone definition, MAX_HOLD counting, swap rule, entry already beyond the stop after a gap), 13 medium ones (e.g. R_TOO_SMALL for source variants, Inside Bar side attribution, non-qualification logging, no precision rule) and several places where paired patterns are not mirrors (Morning/Evening Star SRC-PS stop and TP2, Piercing/Dark Cloud minimum reward and session filter, Tweezer Top/Bottom flags, Rising/Falling close rule). Also: no ACTIVE variant can qualify without its BASE pattern (O-1). Details in `AMBIGUITIES.md`.
